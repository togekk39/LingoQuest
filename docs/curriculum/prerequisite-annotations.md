# Exercise Prerequisite Annotations

[Español (Latinoamérica)](prerequisite-annotations.es-419.md)

Add annotations for new assessed items in `content/source/prerequisites/`. The checker runs as part of `npm run curriculum:verify` in CI. Version 1 is an authoring contract. The three pilot lesson annotations and seven routes are executable examples for future teaching and scored tasks. The existing apps still use their current lesson and pack formats. [Pilot annotations](../../content/source/prerequisites/early-travel.json) · [Schema and validator](../../packages/course-pack/src/prerequisites.ts)

## What to record

| Record             | Required fields and authoring rule                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| File and lesson    | `version: 1`, `targets` and `lessons`. Reuse a target ID across files by declaring it once. A lesson declares its master-plan `id`, `chapterId`, `stages` and `paths`. The chapter and ID must match the master plan.                                                                                                                                                                                      |
| Lexical sense      | Stable target `id`, `kind: "lexical"`, `lemma`, `senseEs` and `forms`. Separate visual `see` from understanding. Register `see`, `saw` and `seen` under the visual sense. Only forms explicitly taught on the path become available.                                                                                                                                                                       |
| Pattern or grammar | A `pattern` has an ID, `descriptionEs` and exact `forms` such as `I'd like`. A `grammar` target has an ID and description of the construction and its function, such as third-person present questions with `does` and the base verb.                                                                                                                                                                      |
| Teaching           | A stage with an ID, `type: "teach"`, `teaches`, `instructionEs` and `exampleEn`. The instruction and example must explain the sense, pattern or construct in the story or Study view before the learner can reach the exercise.                                                                                                                                                                            |
| Context            | A `context` stage has an ID and `supports`. An exercise can also carry `supports`. Each support has `use: "gloss"` or `"inferable"`, a `target` and `reasonEs`. A gloss helps understand that occurrence. An inferable item must be ancillary, recoverable from specific cues and unnecessary to a correct answer. Neither grants prior teaching.                                                          |
| Exercise           | A stage with the exercise ID, `type: "exercise"` and at least one `requires` entry. Include every target-critical dependency in directions, prompt, audio, answer options, accepted results and rubric. A reference is `{ "id": "..." }` for grammar and `{ "id": "...", "form": "..." }` for a lexical form or pattern. A required item cannot also be labeled non-assessed support on the same exercise. |
| Entry path         | A named `path` has `stages` in learner-facing order and `requiresLessons` for earlier annotated lessons that the entry actually requires to be complete. Include Story, direct Study, review shortcuts, branch and skip variants that reach an exercise. An ungated entry lists no prior completion. Each stage must appear in a path.                                                                     |

The checker walks each path in presentation order. A required target must already be taught on that path or come from a gated earlier lesson. For a completed prior lesson, only teaching common to all declared completion paths contributes. Context exposure, lesson position in the master plan and later instruction carry no teaching credit. For forms, normalization only handles Unicode composition and typographic apostrophes. Grammar and senses come from the author's explicit targets and the reviewer's judgment.

## Trace the actual presentation

1. Walk the flow starting from a new learner in Story and in Study. Include every branch, skip and shortcut that reaches the task, and check resume against stable stage IDs. Use the order presented to the learner, which can differ from the order of source fields. Distinguish visible models or transcripts from instruction. A side-by-side answer model makes a task supported even if every prerequisite was taught.
2. Use declared stage IDs as the lesson builder's input for new formats, or compare them to a trace of actual presentation and gates. Before shipping a new format, test parity among exercise IDs, teaching stages, topic IDs and the paths used by both entry points. Test resume after a version change so an exercise cannot use credit for a stage that was skipped or replaced. The pilot does not wire paths to the runtime or require retrofitting legacy packs.
3. On the legacy chapter reader, a browser test checks actual heading order and model visibility for Mexico, Cartagena and Cusco. Its shared section order places dialogue before vocabulary and grammar, the comprehension choice after grammar, and the visible model with open practice. A reader can scroll past the notes, so heading order alone is not proof of a gate. Regression tests use that order to test promoting or moving tasks. Native presentation and new-format path parity still require implementation and testing. [Browser test](../../tests/e2e/chapter-packs.spec.ts) · [Prerequisite tests](../../packages/course-pack/test/prerequisites.test.ts)

| Case                               | What the checker demonstrates                                                                                                                                                                                                                                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mexico · `market-routine-question` | A new question testing the `does` construction during a translated dialogue fails before its formal instruction. The published card's comprehension choice comes later and asks who can go to the market and when. The appearance of `does` in the dialogue does not by itself make that published choice a grammar test. |
| Cartagena · `order-a-replacement`  | The opening dialogue previews `I'd like`. The later grammar note does teach it. A new scoped exercise after that note can pass. Moving the assessment up to the preview or bypassing the note in Study fails.                                                                                                             |
| Cusco · `retell-sighting`          | The dialogue uses `see` and the practice model displays `saw`. A new independent check of `saw` fails when only `see` and the general past rule were taught. Explicit teaching of the past form and sense makes the pilot path pass.                                                                                      |

Missing targets produce chapter, planned lesson, path, exercise and target or form in the diagnostic. Fix the instruction or the path, or review whether the prompt actually requires the target and change the task and annotation together.

```text
chapter=peru lesson=lq-cusco-past.past-irreg path=study exercise=retell-sighting missing=lex.see.vision[saw]
```

CI checks the schema, references, sequence, prior-lesson gates, required/support conflicts and stage coverage for **annotated** material. It cannot establish whether an omitted target is actually required, a gloss is sufficient, the grammar explanation is accurate, an answer key is fair, or a text is level-appropriate. Peer review the content and task in both languages. Reviewers should try the task with the proposed support unavailable, mark necessary knowledge, confirm what each entry actually presents, and test examples and natural variants. Start with the [authoring standard](lesson-authoring-standard.md).
